以下のような仕組みをGoを使って、Kent BeckによるTest Driven Developmentに忠実な開発方法で実装したい。

動画要素のテンプレートが含まれるゆっくりムービーメーカー Yukkuri Movie Maker (YMM) のプロジェクトデータ(テンプレートファイル)と、テンプレートに含まれる要素の配置を示したyamlファイルを指定すると、
それに基づいてテンプレートファイル内の動画要素を適切に構成し、その結果を新しいymmpファイルに出力する。

# Motivation
YMM は素晴らしい動画オーサリングツールであるが、そのプロジェクトファイルの編集効率の向上という点について以下のような課題を抱えている。

- ポータビリティ: プロジェクトファイルに保存される素材ファイルなどのパスが絶対パスになっており、プロジェクトファイルを別の場所に移動した場合、それらを全て書き換えなければならない。
- タイムライン途中の編集が困難: タイムライン上の要素に対して、長さが変わるような変更を行ったとき、動画の後のシーンをずらす作業を手作業で行う必要があるのが大変である。
- プログラム的な編集が困難: タイムライン上の要素をプログラム的に扱う方法が用意されていない。プロジェクトファイルがJSONファイルなので、それを直接扱うスクリプトなどを経由することで可能であるものの、複雑な作業が要求される。

# Solution

YMMPファイルに含まれる要素の構造をyamlフォーマットで定義したものを、「YMMP Scenario (YMMPS)ファイル」と呼称する。拡張子は.ymmpsとする。
YMMPSファイルをYMMP形式に変換するGoプログラムを作成する。

## YMMPS フォーマット

- ymmpファイルのタイムラインの構造を Episode, Sequence, Scene, Shot, Item の単位で構造化して定義し、それらを適切に並べた上でymmpファイルに変換する。
  それぞれの単位は ID 要素を持つことができ、他の要素から必要なときに参照することができる。
  Episode: ymmpファイルで扱われるプロジェクト全体。順序のある複数のsequenceを含み、それらが指定された順番に並べられる。
  Sequence: 順序のある複数の scene を含み、それらが指定された順番に並べられる。
  Scene: 順序のある複数の shot を含み、それらが指定された順番に並べられる。
  Shot: 順序のある複数のitemを含み、それらは同じ開始時刻を持つ（同時に開始される）。
  Item: ymmpのItemに対応。

- Item は、テンプレートに含まれる動画要素（ テンプレートファイルの `$.Timelines[0].Items` 以下の要素それぞれ ）のいずれかに対応する。
  動画要素は、要素内の `Remark` パラメータを要素の識別子として使う。
  その要素は、YMMPSファイルの `_Template`パラメータによって指定される。

- YMMP ファイルは複数のTimelineを保持することができるが、YMMPSではタイムラインが1つであるという仮定をおく。

- Item には Length を指定することができる。この値は、いくつか種類がある。
  - 数値を指定: 指定された数値（秒単位）の長さのitemになる。
  - "_until:SEQUENCE_END" そのitemが所属する sequence の最後まで続く。
  - "_until:SCENE_END" そのitemが所属する scene の最後まで続く。
  - "_until:SHOT_END" そのitemが所属する shot の最後まで続く。
  - "_until:(SEQUENCE|SCENE|SHOT)_END:<ID>" それぞれ、その IDを持つ Sequence, Scene, Shot の最後まで続く。
  - "_auto:*" そのitemが、itemの内容によって自動的に長さを決めることができるとき、その長さにする。
    - 長さの決め方は以下の通り。
      - "_auto:VOICEVOX" 音声の長さ。Serif要素の内容から、VOICEVOXのAPIを使って音声を生成し、音声の長さを取得する。
      - "_auto:VIDEO" 動画の長さ。ffprobeなどを利用し取得する。

- Item に記載された要素は、テンプレートファイルの該当要素を上書き（置換）したうえで出力する。

- YMMPSファイル内で指定される素材ファイルのパスは相対パスで記述される。出力時に適切に絶対パスに変換する。

## サポートされるItemタイプ

基本的にYMMPで表現できるすべてのItemが利用可能である。

### YMMPSファイルのサンプル

```yaml
YMMPSVersion: "1" # 文字列. "1" 以外は拒否

#- ymmpファイルのタイムラインの構造を Episode, Sequence, Scene, Shot, Item の単位で構造化して定義し、それらを適切に並べた上でymmpファイルに変換する。それぞれの単位は id 要素を持ち、他の要素から必要なときに参照することができる。
#  Episode: ymmpファイルで扱われるプロジェクト全体。順序のある複数のSequenceを含み、それらが指定された順番に並べられる。
#  Sequence: 順序のある複数の Scene を含み、それらが指定された順番に並べられる。
#  Scene: 順序のある複数の Shot を含み、それらが指定された順番に並べられる。
#  Shot: 順序のある複数のItemを含み、それらは同じ開始時刻を持つ（同時に開始される）。
#  Item: ymmpのItemに対応。
Sequences:
- ID: sequence1
  Scenes:
  - ID: scene1
    Shots:
    - _Template: "ずんだもん立ち絵01" # ymmp の Item の Remarkがこれと同じ値であるものに対応
      Length: "until:SEQUENCE_END"
    - _Template: "ずんだもんvoice 01"
      Serif: |
        ずんだもんなのだ
      Length: "_auto"
  - ID: scene2
    Shots:
    - _Template: "映像"
      FilePath: "image.png"
      Length: until:SCENE_END
    - _Template: "ずんだもんvoice 01"
      Serif: |
        今日はこの沼について語るよ
      Length: "_auto"
```


## (テンプレートファイル + YMMPS) → YMMP 変換

- YMMPSファイルの構造はymmpファイルのItemsに出力される。
- ymmp ファイルの FilePath 要素は、出力時に出力先のフルパス名に上書きされる。
- item内のファイルパスは相対パスで記載される。相対パスの基準はYAMLファイルの配置ディレクトリとする。ymmpファイル出力時に、絶対パスに変更してから書き出される。
- テンプレートファイル/YMMPSファイルのスキーマはバリデートされる。
  - 無効なYAML構造の場合、詳細なエラーメッセージを表示して終了
  - 必須フィールドの欠如時は、フィールド名と場所を明示
  - 参照IDが存在しない場合、参照元と参照先を明示してエラー


* 実行方法

プログラムは以下のコマンドラインインターフェースを提供する:

```
ymmps-authroizer --template-file <project.ymmp> <YMMPS_FILE_PATH> [options]

必須引数:
  --template-file, -t     テンプレートファイルパス
  YMMPS_FILE_PATH         YMMPシナリオファイルパス

オプション:
  --base-path             相対パスを絶対パスに変換する際の基準パス（デフォルト：YMMPS_FILE_PATHの所属するディレクトリ）
  --validate-only         バリデーションのみ実行
  --verbose               詳細ログを出力
  --dry-run               実際の変換を行わず、処理内容を表示
```
